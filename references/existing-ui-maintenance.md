# 已有链条维护

执行前遵守 [方案与结果审核](../SKILL.md#当前迭代阶段的两处审核) 和 [文件与 MD 一致性](../SKILL.md#文件与-md-一致性)：明确认可且无修改意见时，完成本阶段并自检后继续；提出修改意见时，完成实际产物后必须等用户验收再继续。所有“不重复确认/继续”表述均不得跳过此结果验收；发现未确认的文件与记录差异，先展示并等用户确认，再补录基线或修改资产。

已有界面更新按新建主流程执行：维护固定整理稿，调用项目现成工具输出到正式路径，再按两份 MD 当前有效记录决定恢复项，导出前实际资产只提供取值和核验证据；未记录或不一致项先确认并更新 MD。随后处理设计差异、完成绑定和验证。源 PSD 更新必须先审核本次设计差异，再更新固定 `_UI`；默认不另建带时间戳的整理稿或强制隔离候选合并。

当前迭代阶段还须执行 [两处审核](../SKILL.md#当前迭代阶段的两处审核)：PSD 整理方案与导出后的 Prefab 减法/布局清单分别确认；源差异审核不能代替后者。以下“不重复确认”仅指该阶段具体清单已经获准且范围不变。两个阶段审核修订产生的可复用经验均反馈维护本 Skill；界面具体变化仍分别记录原两份说明。

## 两份 MD 共同驱动迭代

每轮先读取当前两份说明，并贯穿差异审核、PSD 更新、Prefab 处理和代码修复。第一份 `01-PSD修改说明.md` 用于解释源稿与 `_UI` 的命名/分组映射、图层取舍、视觉和人工修正；第二份 `02-Prefab减法与布局说明.md` 用于解释生成节点的减法、Item、布局、适配、绑定与已有功能接入。跨阶段用图层到节点映射关联，不能只按减法表重放，也不能把历史整理差异误当成新增设计。执行后分别更新两份的实际差异、依据和验证状态，并关联本次记录。

## 识别当前状态

关联源 PSD、固定 `<原名>_UI.psd` / `.psb`、正式 Prefab、两份原说明、图片、生成绑定与手写业务代码。检查工作副本状态并保留用户已有改动。明确读取的是保存后的 Prefab、Prefab Stage 还是场景实例；未应用的实例覆盖不等于正式资产，不自动保存无关场景。

同一界面始终维护原 `01-PSD修改说明.md` 和 `02-Prefab减法与布局说明.md`，记录按轮次追加；两份 MD 是整理、恢复和适配决策的权威来源。SHA-256 仅识别版本，不能恢复适配；Prefab、实际参数、组件、引用或资产快照只负责验证和承载 MD 已记录的决策，不能绕过 MD 自行成为恢复依据。缺少记录时把当前实际值和历史未知列为差异，取得用户确认并更新 MD 后再恢复，不编造旧值。

## 复用记录与减少返工

目标是减少重复探索、覆盖和验证，不改变现成工具生成、当前差异审核及两份 MD 的主流程。按本次阶段选用以下约束，不额外建立一套文档、工程配置或替代工具。

- **先提取可执行依据。** 从两份 MD 的当前有效记录提取：源到整理稿及导出节点的映射、最新人工适配、成功调用/保存/预览/清理入口、生成器已知重置项，以及失败方法与适用条件。核对当前实际资产；发现用户新保存的参数、删除的组件或其他不一致时先列差异，取得确认并更新 MD，之后才成为恢复基线。重点核对本轮变化和执行前提，不能读过记录后仍从头试探。已有成功方法核验适用后复用，没有版本、环境或实现变化等新证据，不重试已知失败方法。
- **旧检查先核对当前逻辑。** 复用预览或测试脚本前，检查它使用的字段、API、测试状态和预期结果是否仍符合当前资产及已确认业务。删除的配置、已改变的导航规则、按业务隐藏的按钮不能继续按旧断言检查；据当前需求修正检查脚本，不为通过旧检查而改业务，也不直接跳过真实失败。
- **先核对结构，再集中恢复。** 导出后先保存“刚生成且尚未后处理”的视觉基线，一次比对真实层级、节点映射及组件具体类型，汇总缺失或歧义，不能靠执行到一半报错逐个猜路径。绑定前完成减法、布局及生成所需组件/命名；已知会被生成/刷新覆盖的参数，在最后一次必要刷新后按 MD 集中恢复并保存读回，避免反复配置。恢复清单覆盖 MD 明确记录的根、Canvas、列表、射线、业务组件、用户适配及视觉字段；文字和图片等字段同样由 MD 决定采用生成值或旧正式值。复用恢复脚本前逐字段审阅其写入范围，只有全部写入都对应 MD 当前有效记录时才可批量执行；同节点存在基类和子类组件时定位精确类型。保存方式复用本项目已验证且不会被 Canvas 等驱动器改写的方法，不将某种 Unity API 无条件推广到所有项目。
- **把超时与实际失败分开。** 已知编辑器执行不稳定时，正式写入前用一次无副作用脚本检查实际执行通道，不能只用状态查询成功代替。调用超时或仅证据写入失败时，先查本次产物、内容版本、编辑器模式及编译状态；超时不等于未执行，不立即重发生成。只有实际结果足以证明该阶段完成，才继续后续阶段。结果未知或实际工具失败时停止依赖写入并报告；同一症状完成一次针对性只读诊断仍无新证据时结束试探。仅复用适用于当前状态且在授权内的恢复方法，不连续循环 Play/Stop、重载或覆盖导出，不修改框架或工具来恢复。
- **减少调用和报告自身的故障。** 通过现有允许通道合并同阶段的独立读取、后处理参数与结果核验，保留编译/类型加载等真实阶段边界，不跨依赖并发操作同一编辑器或资产。外部调用回包与编辑器内部结果文件使用不同完整路径，例如 `*-coplay.json` 与 `*-outcome.json`；Windows 下按不区分大小写检查冲突。优先复用已有连接/调用封装，不为减少启动开销新增项目工具。
- **预览必须包含验收与清理。** 复用已成功的渲染路径，将所需尺寸在同一阶段完成；图片写出或工具返回成功不等于显示通过，检查图像非空并实际查看关键视觉。硬编码设计样例或从参考节点复制出的预览只能证明静态素材与排版，必须标记为设计预览，不能作为运行时一致性证据。存在动态 Item、状态、图片、文字或显隐时，还要使用真实运行数据或与真实绑定路径等价的数据入口验证模板映射，重点比较文字框高度、基线、图片选择和状态结构。建立临时场景前记录所有权、原活动场景及 dirty 状态，明确独立可调用的清理入口；渲染后立即清理并核验，不把关键清理只托付给延迟回调。失败时也只清理本次临时对象，不保存无关场景或清除用户 dirty；清理能力不足时报告状态，不临时改框架。
- **验证有明确结束点。** 针对本次差异及重生成影响确定必要检查：新增状态覆盖切换/复用，背景覆盖选定比例，生成刷新覆盖编译、绑定和适配。这些检查通过后结束；只有新改动、失败或未解疑点才补跑受影响项，不重复完整导出或无关回归。保留必要证据，原两份 MD 各追加本阶段结果，复用输出而非重复抄写日志；阻塞发生时记录阶段、等待原因和实际耗时，不承诺固定完成分钟数。

- **最后修改后补验受影响部分。** 已完成检查后又修改文字效果、布局、资源引用或代码时，对受影响部分补做相应验证；例如换材质后重新查看文字效果，无需重跑无关流程。截图和运行结果应注明对应的资产或代码版本，不能用修改前的结果宣称修改后已通过。未受影响的检查可以沿用；未补验的部分明确记录。

## 整理稿修正后续作

用户修改固定 `_UI` 后，以当前修正版续作，按 [导出前整理稿检查](psd-preparation.md#导出前整理稿检查) 核验，不重新从源覆盖其修正。源 PSD 本身更新时保留源文件，根据旧整理稿和第一份说明识别仍适用的命名、分组及修订，将新源与当前 `_UI` 的差异结合当前说明中的历史记录分类汇总给用户审核，同意后才维护同一固定 `_UI`。更新前保留必要的可恢复内容；恢复副本只用于恢复，不成为新一轮工作稿或另一个交付版本。

## 源 PSD 更新主流程

**当前差异审核是更新固定 `_UI` 的前置条件。** 先只读比较新源 PSD 与当前 `_UI`，结合当前说明中的历史记录区分新设计差异、历史整理差异和人工修正；不能将二者全部差异当成新设计。总结拟保留、替换、删除及未确定项，说明影响并交用户审核，同意后才写入固定 `_UI`。笼统的“执行完整流程”“直接更新”授权不能替代本次具体差异审核；已经审核的同一差异与范围，后续不重复确认。审核期间可独立补齐恢复基线，但不得提前更新整理稿或执行依赖该更新的正式导出。

1. **补齐当前基线。** 在任何会覆盖正式产物的导出之前，读取原两份说明与当前实际资产，先列出尚未记录的人工适配差异，取得用户确认后再补录。保存适配所需节点身份、层级、锚点、pivot、位置、尺寸、缩放、布局组件、文本设置、列表配置、模板、必要组件和序列化引用。记录相关 `.meta` / GUID、内部对象及外部引用；可能被生成器覆盖且无法由参数恢复的内容，保留可恢复资产快照。不能只留摘要就开始覆盖。
2. **审核通过后维护固定整理稿。** 记录本次具体差异与用户同意依据，保留源 PSD，在固定 `_UI` 上完成主流程中的整理和导出前检查，维护第一份说明。检查新设计与旧人工修正的真实差异，不机械恢复与新设计冲突的旧值。
3. **调用现成工具正式导出。** 核对真实 Importer、入口、配置和写入范围，沿用正式模块名与路径执行工具菜单、按钮或同一方法。切图、Texture、Atlas、Prefab 均遵循当前工具配置与已授权更新范围，不默认创建新名字或隔离候选。导出前核对共享图片影响，不能因同名就认定可复用；涉及其它界面的共享变化不属于默许范围。工具失败时停止依赖该步骤的写入，报告已写文件和当前状态，保留恢复依据；文件还原由用户处理，不自动回滚。
4. **快速对比并恢复适配。** 比较刚生成视觉基线、旧正式基线、原说明及新设计，以两份 MD 的当前有效决策为恢复白名单，恢复仍适用的用户适配、组件和业务接入结构，按新建主流程落实减法、Item 和布局。先分列已完成生成变化、恢复既有配置和本轮修改；恢复组只列 `[恢复]`，不计为本轮修改；修改组只列 `[删除]`、`[修改]`、`[新增]`，并写明 MD 记录值、当前生成值、目标值和依据。未列出的节点和配置保持当前生成结果，不枚举不变或不处理对象。只有 MD 已明确记录为运行配置或用户适配的字段才标为 `[恢复]`；旧正式资产只验证该记录，仅因旧 Prefab 有值不能恢复。MD 缺失或与资产不一致时先列差异，取得用户确认并更新 MD 后再执行。新目标使用 `[修改]`，此前不存在的内容使用 `[新增]`。后处理完成后做全部序列化字段差异审计，确保相对刚生成基线的每项变化都在已确认清单中；不直接重放过时固定参数或整个节点。本次差异已审核且后续仍在同一范围时继续执行，不因恢复适配或进入代码阶段重复确认。发现任何未确认的文件与 MD 差异时均先提交确认；用户提出过修改意见的，本阶段完成后须等待结果验收。其他超范围或不明确项也应具体澄清。
5. **生成、修复、编译、刷新。** 调用项目现成 UI 生成工具前记录 `[工具生成]` 允许写入的组件与字段类别；修复清单明确包含的手写业务引用，编译且类型可加载后调用现成刷新入口，再检查实际序列化引用。不要手改生成文件。刷新可能回写根 Canvas/Transform；完成最后一次集中恢复后，继续完成清单内已有功能适配并再次请求编译、确认类型加载与 Console。全部写入结束并保存后，以最初刚生成视觉基线对最终 Prefab 做全部序列化字段差异审计：手工与恢复变化逐项关联已确认清单，权威工具变化逐项关联调用前白名单。功能适配若修改 Prefab，必须纳入已确认动作并审计修改后的最终资产。新发现的代码行为或作用域须补清单确认；任何其他变化均须按来源恢复或进入 MD 不一致确认，不能报告完成。
6. **旧业务适配及验证。** 代码仅修复受变化影响的旧逻辑；差异属于以前已实现的功能时，补全其对新节点与数据展示的适配，依据现有代码与调用链证明已实现。从未实现的功能不自动补做，记录缺口，不把新增视觉节点当作业务实现授权。验证显示、列表、隐藏重开及受影响功能，审阅差异和引用，追加原第二份说明；区分静态检查、Unity 编译与实际运行验证。

## 正式写入前复核

本节适用于固定 `_UI` 更新、正式导出和后处理；中断恢复或用户同时编辑后重新核对，不替代前述当前差异审核。

- 写入前重读输入与目标，比较基线以来的真实变化。新用户设置与 MD 不一致时先列出差异，经用户确认后纳入最新恢复基线，已审核的同一差异范围继续有效；源设计又变化或出现新冲突时，只补审新增差异。
- 保持正式资源名称、路径与 `.meta` / GUID。工具重导出仍可能更换内部对象身份，核对 Sprite 子资源、生成字段、外部序列化引用、动画路径、Prefab 实例及 Variant 覆盖；同名同路径不代表引用必然保留。
- 记录真实恢复来源和字段值，不把 SHA-256 当作可恢复副本。发现无法恢复的既有内容时先补齐证据或说明具体限制。
- 恢复及处理以本次设计和仍适用的用户适配为准，不能把更新请求扩展成无关业务改造或资源迁移。

## 改动较多时重建

完成本次差异审核后，正式工具重导出是本维护主流程的一部分，不因界面已存在而另设重复审批。结构变化较大时，在原说明中记录需要恢复的适配、组件和引用以及实际处理方案，沿用正式名称与路径。若将超出用户授权删除业务能力、改变交互或影响其它界面，只澄清该新增范围；不重复询问已批准的导出与更新。

## 用户直接修改适配

用户已保存的适配先保留；与 MD 不一致时先展示差异，确认后作为最新基线。只要求记录时，读取实际资产、对照原第二份说明，补录参数和显示检查；未知原因写“用户调整，原因未说明”。不重导出、不重放旧脚本；节点与绑定不变时不重跑绑定、不改业务。后续完整更新先补齐并使用这份新基线。

用户委托 Agent 调整适配时按明确范围执行、验证并记录，不误判成只读观察。仅参数变化且绑定不变时无需生成或刷新。发现实际结构/绑定变化，再执行所需工具步骤。

## 新视觉节点的业务补充边界

以对应业务功能是否存在判断，不以该节点此前是否有专门代码判断。新设计为已有功能增加视觉反馈时，补齐生成绑定后的业务状态、显隐和刷新逻辑，并验证状态切换；这属于已有功能的完整维护，不是擅自扩展新业务。审核差异时就列明这种接入需求。

例如，界面已有条目选中状态，本轮新增选中框，就需要将选中框接入当前选中状态及切换刷新，不能只保留静态图片。相反，头像一直只作展示、没有头像数据或交互业务时，不自动增加头像加载、点击或更换功能。具体页面节点与业务来源记录在该界面的两份 MD 中。

## 仅修改手写功能代码

现有节点和绑定满足需求时，只核对调用链并修改业务逻辑、编译、验证，不导出 PSD、不调整 Prefab、不要求空的资产确认清单。确需节点或绑定变化时按已有授权补齐资产与现成工具流程，不按名称查找兜底，不手改生成文件。

## 工具边界与交付

本 Skill 不得修改框架、PSD 导入器、UI 生成器或其它公共工具源码；不能通过工具修复、替代生成器或自写烘焙切图补足能力。手写代码只允许本次业务逻辑；UI 资产编辑与现成工具调用沿用项目规则。工具缺失或不支持设计效果时，报告具体能力限制与已完成状态，不扩展为框架/导入器开发任务。

# Prefab 精简与布局

本文任何旧的“两份 MD”表述只适用于 PSD/Prefab 字段；涉及 Prefab 导出后的 Unity 图片资源归纳、改名、移动、引用切换、合并或清理时，必须读取并更新 `03-图标归纳与命名说明.md`；存在实际资源动作时，第三份 MD 的用户确认是执行前置条件，无动作时只记录盘点。PSD 图层及固定 `_UI` 命名只归第一份。

## 生成视觉基线与后处理边界

现成 PSD 工具刚生成且尚未执行任何减法、布局、代码生成或刷新操作的 Prefab，是本轮视觉坐标基线。导出成功后先记录其版本或保留可读回的恢复证据，再开始后处理；不能只保存旧正式 Prefab 而没有新生成基线。

后处理按字段归属执行：

- PSD 工具生成的视觉字段提供本轮比较基线，包括普通视觉节点和 `_@` 模板内部的 RectTransform、文字框、字号、对齐、图片、颜色及效果；最终采用生成值还是当前阶段及关联字段所需 MD 的有效记录决定。
- 正式 Prefab 独有的运行配置可以从重生成前基线恢复，包括根适配、布局组件、滚动配置、按钮与射线、业务组件、绑定及明确记录的用户适配修正。
- 同一节点不能按“恢复整个节点”处理。逐组件、逐字段判断；运行配置与 PSD 视觉字段共存时，只恢复清单中明确的运行字段。
- PSD/Prefab 字段由第一、第二份 MD 的当前有效记录决定；涉及导出后图片或图标的归纳、改名、移动、引用切换、合并或清理时必须同时读取第三份 MD。旧 Prefab 或旧快照只用于验证 MD 已记录的值，不能独立成为恢复依据。MD 要求恢复则覆盖生成值，MD 要求采用新稿则保留生成值；MD 未记录时先列为未确认差异，取得用户确认并更新 MD 后才执行。
- PLink 后处理只通过 Coplay MCP 的直接工具或请求载荷按最小字段操作。禁止生成、保存、读取、传递或执行恢复脚本和任何其他外部脚本文件；历史脚本只能作为不可执行的事件记录，不能用作本轮取值、审计或写入依据。未列入已确认清单的 RectTransform、TMP 文本框、字号、字体、文字颜色/透明度、水平/垂直对齐和效果字段禁止写入；射线、布局、文字效果和状态迁移按最小独立操作执行。

减法和布局完成后，比较“刚生成基线 → 后处理结果”的全部序列化字段差异；第三份 MD 图片处理引起的 Prefab 引用变化也须对应已确认资源清单，并在代码生成前重新审计；代码生成、绑定刷新、最后一次集中恢复、清单内已有功能适配及再次编译完成后，再以同一刚生成基线比较最终保存 Prefab。绑定前每项差异必须对应已确认的 `[恢复]`、`[删除]`、`[修改]` 或 `[新增]`。最终审计中，手工与恢复变化仍对应上述动作；只有逐项命中工具调用前字段白名单、且由权威代码生成/绑定工具实际产生的 Mono、绑定引用和根配置变化才能标记为 `[工具生成]`。该标记不适用于 Coplay 调用外的写入、手工 Prefab 写入、白名单外字段或超出生成作用域的变化。任何无法归因的变化都视为失败；第一次失败时不得进入代码生成与绑定，最终审计失败时不得交付完成。功能适配若再次修改 Prefab，必须把相应字段纳入已确认动作并以修改后的最终资产重做审计。

执行前遵守 [两处审核与结果验收](../SKILL.md#当前迭代阶段的两处审核) 和 [文件与 MD 一致性](../SKILL.md#文件与-md-一致性)：正式 Prefab 导出后必须基于实际节点和当前值提交 **Prefab 减法与适配审核** 清单，不能用此前的 PSD 方案确认代替。用户未提出修改意见时，确认后执行并自检，不增加 Prefab 结果验收；用户提出修改意见时，完成实际产物后必须等用户验收再继续。发现未确认的文件与记录差异，先展示并等用户确认，再记录基线或修改资产。

源 PSD 更新须把 [源更新差异](psd-preparation.md#源更新先审核差异) 纳入同一份 PSD 整理方案审核，用户同意后才更新 `_UI`；该内容不是额外确认门。PSD 方案直接确认时自检后导出，方案有修改意见时完成结果验收后导出。Prefab 正式生成后读取实际节点、当前值、第二份 MD 和正式基线，提交减法、布局、工具生成及已有功能影响清单；不得重新枚举已经完成的 PSD 动作。审核有修订时将可复用经验反馈到本 Skill 的减法/布局规则，原第二份说明记录该界面的实际修改及验证。业务仅修复受影响旧逻辑或补全此前已实现功能的差异接入；此前未实现的功能不自动补全。

在视觉 Prefab 已生成、需要精简节点绑定、核验 `_UI` 已落实的 Item 模板复用或配置适配布局时读取。此阶段处理运行资源，不在 Prefab 中首次决定模板结构；PSD 保留设计与外观参考，除非本次同时要求回写。优先配置 Unity 内置和项目既有组件，不为整理/适配新增自定义 MonoBehaviour、工程内辅助 `.cs` 或永久菜单。完整流程在此阶段完成后继续调用现有绑定生成，完成必要手写引用修复，再编译和刷新。

## 减法前清单的比较与动作标记

对照第一份 MD 中已确认且在 `_UI` 落实的模板结构，逐组盘点刚生成 Prefab 中的重复单元与参考样例，并在审核清单中核对其类别：独立运行实例、唯一模板内的条件状态，或仅供设计参考而应删除。写明承接节点、引用与局部几何，以及参考根最终保留/删除动作；模板所需视觉或遮罩若在 `_UI` 遗漏，回 PSD 阶段确认和整理，不在 Prefab 中首次迁入并设计模板。用途未定时列为待确认，不能以“暂留参考”作为已完成的取舍。此盘点属于同一次 Prefab 审核，不增加一个确认门。

提交 Prefab 减法与适配审核前，列明三份状态：重生成前正式 Prefab/当前 MD 的有效基线、刚生成且尚未后处理的 Prefab、计划完成后的正式目标。清单必须使用刚生成 Prefab 的实际节点和当前值，不能在生成前用“生成后读回”占位完成本阶段审核。报告分为“已完成的生成结果”“恢复既有配置”和“本轮修改”，不能把已经由 `_UI` 或生成器完成的删除、恢复旧值与下一阶段的新修改写在同一组无标记列表中。

| 标记 | 含义 | 是否会写入当前 Prefab |
|---|---|---|
| `[删除]` | 当前仍存在，目标中移除 | 是 |
| `[恢复]` | 生成器重置或丢失，按当前阶段及关联字段所需 MD 的有效记录还原；旧正式资产只提供取值证据；不计为本轮修改 | 是 |
| `[修改]` | 当前值改为新的目标值，不等于恢复旧值 | 是 |
| `[新增]` | 旧正式基线和当前生成结果都不存在，本轮新建 | 是 |

生成阶段已经发生的变化使用完成态，例如 `[已删除]`、`[已修改]`，并注明核验对象；它们不是下一阶段操作。后续操作分成两组：`恢复既有配置` 只列 `[恢复]`，`本轮修改` 只列 `[删除]`、`[修改]`、`[新增]`。开头注明“未列出的节点和配置保持当前生成结果”，不逐项列不变或不处理对象。每个待执行项写成“稳定节点/组件：MD 当前有效记录｜当前生成值 → 目标值；旧资产取值证据”，相同动作可合并枚举，但仍要保证每个对象的当前状态和目标明确。`[恢复]` 必须指向 PSD/Prefab 字段对应的第一、第二份 MD 具体有效记录；涉及导出后图片或图标的归纳、改名、移动、引用切换、合并或清理时另按第三份 MD 决定资源动作，第二份仅记录 Prefab 字段影响和第三份记录编号。MD 没有记录时列为待确认，不能用旧资产或“恢复既有布局”代替决策。

已有正式 Prefab 或用户适配修订时先读取 [已有链条维护](existing-ui-maintenance.md)：生成前核实旧正式资产与当前阶段所需 MD，未记录或不一致项先列差异、取得确认并更新对应 MD。已有维护默认只导出图片；整体大改先询问是否重生成，已明确批准同一次重生成后不再重复询问，但正式 Prefab 生成后仍须完成本轮减法与适配审核，再按确认清单恢复 MD 当前有效配置并处理实际差异；不能跳过 MD 不一致确认或修改意见触发的结果验收。只导出图片且绑定结构未变时不执行完整恢复/绑定链；用户仅改适配时按同一差异确认规则更新 MD，不适用本节完整重放和绑定顺序。

## 先精简运行职责

为待调整节点记录原定位、用途、保留的视觉、绑定变化及理由。已有面板先检查手写代码、动画和序列化引用；“当前没有显隐调用”不能证明节点无需动态内容或交互。

使用 [阶段溯源记录](traceability.md) 中的第二份模板，在重新生成前记录旧正式 Prefab 的可恢复位置、稳定节点定位、布局/组件参数及引用；生成后另记未经后处理的工具输出与调整意图，完成后填写实际变化、原因和验证。仅记录摘要不能支持恢复适配。布局完成及绑定刷新后的 Prefab 指纹分开保留，使说明能够对应具体资产状态。

| 节点职责 | 处理 |
|---|---|
| 始终显示的背景、边框、静态文字 | 保留视觉；无运行访问需求时去绑定标记 |
| 仅用于弹窗暗化的均匀纯黑半透明遮罩 | 已确认方案允许不用大图；优先引用 common 中已有的 mask，图片自带颜色和透明度时使用白色 tint、Image Alpha=1，不叠乘目标透明度或反算补偿系数。没有适用公共 mask 且用户确认使用无 Sprite 的纯色 Image 时，才设置黑色及目标 Alpha；核对层级、铺满和需要的射线拦截 |
| 动态文字、图标、进度、点击目标 | 保留对应组件或交互绑定 |
| 纯锚点/布局容器 | 保留层级职责，无代码访问需求时不绑定 |
| 需要整体显隐、移动或播放状态的功能组 | 保留所需组引用；勿把独立控制需求误判为冗余 |
| 可由同一模板表达的重复结构 | 保留一个模板，明确实例数量、数据来源及生命周期 |

绑定精简不等于视觉删除。移除空容器前确认它不承担锚点、蒙版、布局、动画或组件引用，并验证子节点的坐标、缩放与绘制顺序。装饰 Graphic 的 Raycast Target 可在确认不承担点击命中后关闭；不能关掉唯一的交互命中面。

复用公共 mask 时，读回 Sprite 引用、Image tint/Alpha 和影响显示的祖先 CanvasGroup Alpha，确认没有重复叠乘；既有显隐动画不属于新增静态透明度补偿，不因此删除或改写。历史记录中的目标透明度或乘积补偿系数不能自动成为恢复项；与本轮明确决定冲突时按维护入口更新对应记录，不擅自修改正式资产。

纯色遮罩替换必须列入已确认的 Prefab 后处理清单。对比生成基线时，逐项记录原大图节点或引用的处理、Image 颜色与 Alpha、RectTransform 覆盖范围、绘制顺序及 Raycast Target 是否承担阻挡点击；保存后在目标宽高比和弹窗开关状态下核对视觉与交互。旧图已导出时，先在第三份 MD 记录待清理项，待本阶段解除引用并完成字段审计后，再回到第三份核验共享引用并执行已确认的资源清理；不得因 Prefab 改用 Image 就直接删除资源或 `.meta`。

## 按钮射线范围

按钮应按实际点击难度适当扩大命中区域，尤其是关闭、小图标等视觉尺寸较小的按钮。优先在按钮本体已有的可射线 Graphic（如 Image）上配置 `Raycast Target` 与 `Raycast Padding`，保持原视觉尺寸、布局、Listener 和点击动画目标不变，不为扩大命中另套透明按钮或运行时补组件。

当前 UGUI 支持该字段时，负 Padding 向外扩展命中范围；四边 `-10` 可作为初始试调示例，不是所有按钮的固定值。根据实际尺寸、Canvas 缩放、边缘可点性和相邻控件间距选择各边值，已有足够点击面积的按钮不机械扩展。检查父级裁切、CanvasGroup/射线过滤与装饰遮挡，Padding 不保证绕过这些限制；不得让扩大区域侵占相邻按钮、独立交互或滚动操作区域。

将采用的按钮路径、Graphic、四边 Padding、调整依据与验证结果并入第二份 MD 的 Prefab 适配清单；保存后读回字段并纳入重生成恢复。验证按钮视觉内、四边扩展区域、相邻控件及滚动手势，只触发预期事件且点击动画仍作用于按钮本体。静态读回与实际交互验证分别记录，未运行不写通过；仅图片维护不因此扩展为 Prefab 改造。

## 整体点击动画的按钮层级

需要背景、图标、文字等整体响应点击动画时，保留外层 `_@` Item 根承接布局，将需要一起动画的视觉内容放在内部 `_b` 按钮节点下，由该按钮整体承接现有点击动画。已有背景节点适合承载时直接复用，不重复套按钮；否则增加包住整组视觉的按钮父节点，保留各子节点的实际显示位置、尺寸与绘制顺序。

- `_b` 按项目现成生成器绑定为 `UIEventTriggerListener`，不把它误当作必须新增 Unity `Button` 组件；注册沿用现有点击接口与动画机制，不另写动画脚本或运行时补组件。
- 保留覆盖目标区域的有效点击命中面；装饰子节点不得意外拦截，独立子按钮仍保留各自交互职责。需要随整体动画的边框、选中反馈等也放入同一动画层级；明确不应参与者保留在外层。
- 同一 `_@` 模板有普通、广告、锁定或其他互斥按钮分支时，**每个可显示 `_b` 都单独配置在自身 GameObject 上的 Listener 与可射线命中的现成 Graphic**；不能只让默认显示分支可点，也不能借用兄弟按钮或装饰子节点的命中面。状态隐藏时可无运行委托，但切换为可见后必须注册对应回调并能命中该按钮本体。
- 外层 Item/布局占位保持稳定，内部按钮播放缩放；核对 pivot、点击范围与布局的 Child Scale 等设置，避免动画推动相邻项。不能只给背景绑定点击而把文字、图标留作同级，导致只有背景动画。
- 迁移层级前核对既有引用、动画路径和独立交互，调整后用现成工具重生成并刷新绑定；在原第二份说明记录按钮承载节点、子节点迁移、命中范围和原因，并纳入重生成恢复。验证整组动画、单次事件触发、布局稳定及 Item 复用后的状态；未进行运行验证时如实注明。

## 模板与实例

减法执行后逐组回读：必要视觉、遮罩和状态已由正式模板或实例承接，引用与局部定位已核对；不参与运行的参考根已实际删除；保留的根有明确运行职责。仅隐藏、改名或声明后续再删，不满足本阶段完成条件。把这份核销结果和全部字段差异审计写入第二份 MD；未完成时不得进入第三份 MD 的正式图片处理，也不得调用代码生成、编译或绑定刷新。依赖生成类型的运行验证在正式绑定后执行，不作为减法前置要求。

先比较字段、组件类型、布局和变化数据，结构不同的控件不强行合并。参考外观的切图、字体和文字需有保留或数据接入方案；只有替代实例方案明确后，才从最终运行 Prefab 移除参考节点。只交付 Prefab 时，可以保留唯一模板并说明显示实例的接入点，不虚构业务列表。

模板可以本身作为首个显示项，也可以隐藏后用于克隆。隐藏模板通常不参与 LayoutGroup 排列；克隆继承隐藏状态时必须显式激活。绑定前核对最终父节点、兄弟顺序及模板是否意外占位；完成减法与字段审计后再用现成生成器创建 Mono、编译并刷新引用，不能把普通参考节点当作已绑定实例。PLink 细节见 [通用 Item 判定](plink-integration.md#通用-item-判定)。

减法清单删除参考节点前，逐项判定其属于独立运行时实例、同一模板的状态、仅用于设计说明的样例，还是无运行时用途。合并为一个 `_@` 后，先在刚生成的 Prefab 核对每个互斥状态根及必要子节点、引用和局部 RectTransform，确认状态切换时共享同一锚点或已明确记录的对齐基准，再删除参考节点。PSD 小眼睛只用于识别和保留状态，不要求导出的 Prefab 复现 PSD 默认显隐，也不据此改写 Active；运行时显隐由业务判断。已实现且属于本次范围的状态切换须验证对齐与显示，未实现的业务不据此补做。

动态文字若需求定义为一个内容，模板只保留一个绑定节点；视觉上的拆分不能自动扩展成多个字段。状态合并后，对每个已确认状态静态核对所需节点、引用及局部布局；仅对已实现且属于本次范围的业务，验证初始态、状态切换、重复使用或重新打开后的显示与布局。未实现的切换记录为未验证，不补做业务逻辑。

## 锚点与布局组件

View 是全屏承载容器，须铺满面板根节点：`anchorMin=(0,0)`、`anchorMax=(1,1)`、`offsetMin=offsetMax=(0,0)`（`sizeDelta=(0,0)`、`anchoredPosition=(0,0)`）、`localScale=(1,1,1)`。下述中心或边缘锚点规则用于 View 内的功能区域，不用于把 View 缩成内容包围盒。调整 View 时核对并保留子区域已确认的设计位置，不把整体内容强行拉伸；将必要的子区域位置调整纳入同一 Prefab 清单。绑定刷新后保存并独立读回 View 参数，在基准及选定宽高比验证实际覆盖范围；不以根节点已全屏代替 View 验证。

有明确底图界定的内容整体时，在 View 下用 Root 承载底图及对应内容；Root 按该内容区域设置尺寸、锚点和位置，承接整体定位、缩放及已有动画目标，View 保持全屏。核对底图与内容的绘制顺序、局部几何、绑定及动画引用，保留迁移前已确认的视觉；关闭按钮等元素是否归入 Root 取决于是否随该整体变化，不按名称机械移动。Mask 不放入 Root，独立于该底图的区域可继续放在 View 下。将容器与实际迁移节点列入同一 PSD/Prefab 阶段清单，复用已有等效容器，不重复嵌套；既有界面只在本次授权范围内调整，不新增动画或脚本来补偿层级。

先确定整体区域与屏幕中心、边缘及安全区的关系，再安排区域内部的序列。普通内容区域默认以画布中心为锚点和定位基准，保留相对中心的设计偏移；货币、人物信息、导航栏等确实贴边且需要随边缘或安全区定位的区域，才采用对应边缘锚点，并记录具体依据。背景覆盖和已有布局组件驱动的子节点按各自职责处理；第二份 MD 已确认的不同锚点方案优先于默认值。图标上叠加的冷却、文字和特效仍保持相对定位；锚点选择不决定文字自身的水平或垂直对齐。

| 需求 | 选择与约束 |
|---|---|
| 同级元素从左到右或从上到下排列 | HorizontalLayoutGroup / VerticalLayoutGroup；按设计设置顺序、间距、Padding、Child Alignment |
| 单元需要确定宽高 | 默认采用子节点当前 RectTransform 实际尺寸，不添加 LayoutElement、不为凑排版统一改大小；父组 Control Child Size 与 Child Force Expand 的 Width/Height 均关闭，通过 Spacing、Padding 和对齐排版。MD 已确认其他驱动方案时按 MD 执行 |
| 容器需随内容大小伸缩 | ContentSizeFitter，仅启用需要的轴；确认父布局没有同时控制该轴尺寸 |
| 装饰或模板需要排除出布局计算 | 按用途放到布局容器外或隐藏，不为此新增 LayoutElement；勿将显示实例一并排除 |

布局默认遵循“子节点多大就按多大排”：不新增 LayoutElement，也不使用其 min/preferred/flexible 尺寸驱动此排版。MD 已明确记录其他经确认方案时以 MD 为准。已有 LayoutElement 先核对引用及 ignoreLayout 等职责，不因本规则批量删除用户已有组件；需要替换其职责时纳入本次明确的后处理范围。记录实际四项开关、子节点宽高、间距、内边距、驱动者和理由，重生成后按 MD 恢复。

同一 RectTransform 的同一轴只由一个系统决定尺寸，位置也只由一个系统驱动。添加布局前检查运行脚本是否写 anchoredPosition/sizeDelta；移除或迁移冲突的控制，不让布局和脚本反复覆盖。固定区域不为“配齐组件”添加 ContentSizeFitter。需要缩放/脉冲效果时通常保持 Child Scale 关闭，或将效果放到单元内部的视觉子节点，避免相邻项随动画抖动。

布局组件无需代码绑定标记；存在明确运行访问需求时，才按项目支持方式暴露引用。参考尺寸、CanvasScaler、根 Canvas 与安全区服从现有运行框架：不要在嵌套 Canvas 上盲目添加第二套缩放或安全区控制。

## 字号、字体与颜色视觉还原

字号必须逐文字节点核对，不能从同类节点批量推断，也不能只比较 PSD 与 Unity 的数字。PSD 的点值、导入器解析值和 Unity `fontSize` 是三类证据；最终目标是在本次基准尺寸及选定宽高比下，使用实际字体资源还原设计中的字形大小、行高、基线与占用范围。

1. **记录 PSD 有效状态。** 从固定 `_UI` 的 Photoshop 字符/属性和段落面板记录文字路径、各段实际字体名与显示字号、填充颜色、文字/图层不透明度、文字变换/缩放、字重、行距、字距、段落对齐、文字框和设计预览，并把底层 `EngineData` 或检查脚本解析值单独列为诊断证据。两者冲突时，以 Photoshop 实际显示值和设计画面为源依据，不能把底层原始值冒充实际字号、颜色或对齐。若同一图层有多个字体、字号、颜色或变换，标为非单值文本，不能用首段属性代表整层。
2. **记录刚生成状态。** 读取实际组件类型、映射后的 Font/TMP Font Asset、`fontSize`、该字号来自 PSD 属性还是文本边界/图层边界/默认值等回退来源、UGUI Best Fit 或 TMP Auto Size 的开关及上下限、UGUI/TMP 的文字颜色、TMP 顶点渐变及 Color Gradient Preset 的启用/引用、富文本颜色与颜色标签覆盖开关（按当前 TMP 版本实际字段）、影响字面的现有材质 Face Color、Graphic 与祖先 CanvasGroup Alpha；UGUI Text 记录组合式 `alignment`/`TextAnchor` 并拆解其水平与垂直语义，TMP 记录当前版本实际的水平/垂直对齐字段。另记录行距/字距、RectTransform、`localScale`、影响显示的祖先缩放和基准 Canvas 配置。字体缺失后使用 fallback、字号或颜色回退、整数取整、文字变换或段落对齐未表达时，都单独记录，不能归成“看起来接近”；回退值不能未经 `_UI` 证据和视觉核验直接成为恢复基线。
3. **先定原因再改字段。** 字体资源不一致先核对项目已有字体映射及实际 fallback；不得自动修改全局字体映射、fallback 或导入器，只能把本节点字体资源的处理列入 Prefab 减法与适配清单。颜色不一致时先判断是文字颜色、顶点渐变/富文本、Graphic/CanvasGroup Alpha 还是现有材质共同造成；只修改清单中已确认的节点字段，不修改共享材质，也不把 Photoshop 色值未经实际渲染核验机械写入 Unity。缩放链或文本框错误按布局清单处理；只有实际字体和缩放基准正确后仍有字形大小偏差，才修改该节点的 Prefab `fontSize`。混合字体、字号或颜色若当前组件/导入结果无法表达，列明需拆分节点、采用项目已有富文本能力或接受差异，未经确认不自行改结构。UGUI 需要整数时，在字体与缩放正确后比较相邻整数的实际显示，采用清单中已确认且更接近设计的一项；两者都无法还原则记录能力差异，不使用 `localScale` 补小数。不得通过父节点缩放、补空格、运行时代码改字号/颜色/对齐或擅自启用自动缩字掩盖静态文字错误。
4. **逐节点核销并验收。** 先从第二份 MD 提取当前有效的文字与布局决定，再对照固定 `_UI` 的文字层、刚生成 Prefab 的文本组件和最终保留节点，列出数量及稳定路径映射；删除、合并或动态新增节点分别关联已确认动作。每个最终文字节点都在第二份 MD 的字号/字体表和颜色/对齐表核销，新节点和保留生成值的节点也不能漏项。使用实际文案在基准尺寸和本次选定宽高比，比较实际渲染颜色与透明度、字形可见高度/宽度、基线、行距、文字框内留白及与邻近图形的关系；属性相同、与旧 Prefab 相同或没有遮挡都不能代替该比较。逐节点记录 MD 决定、PSD 证据、刚生成值、目标值、实际字体资源、修改字段、显示结果及通过/未通过/未验证；有未核销或仍不符的节点时，Prefab 文字验收为未通过或部分完成，记录差异不等于通过。重生成后按该记录恢复并再次核对。

无法可靠读取 PSD 的混合样式或文字变换时，记录能力限制并以设计预览和实际字体渲染作人工对照，不编造精确换算公式，也不把一次界面的经验固化成全局字号比例。

## 文本对齐与溢出

先按实际用途区分固定文本与动态文本，沿用当前的 UGUI Text 或 TextMeshProUGUI，不为检查而迁移组件：

- **固定文本不额外做防爆框处理。** 标题、固定按钮文案等内容不会变化时，按实际文案核对对齐和显示即可；不构造长文案测试，不额外增加自动缩字、换行或溢出策略。当前文案已经显示异常时，只修复实际问题。

- **按设计对齐并读回字段。** 逐节点从固定 `_UI` 的 Photoshop 段落面板和设计画面确定左/中/右及需要表达的垂直关系；UGUI Text 记录组合式 `alignment`/`TextAnchor` 及其水平、垂直语义，TMP 记录当前版本实际的水平、垂直对齐字段，同时记录文本 RectTransform 相对目标区域的位置、内边距与行距。文本框居中不代表字形已经居中，居中锚点也不能替代文字对齐设置；不能因刚生成值已有默认对齐就跳过核对。原本左对齐或右对齐的内容保持设计意图；Photoshop 与 Unity 对齐语义无法一一映射时，以实际字形边界、基线和设计画面验收，并记录采用值及差异。图标加文字的按钮按设计检查整组与文字各自的位置，不把文字单独强拉到按钮中心。保存后必须读回实际 UGUI 组合值或 TMP 两轴字段并重新预览。
- **先核对可用空间。** 按 [字号、字体与颜色视觉还原](#字号字体与颜色视觉还原) 确认实际字体、字号、颜色及缩放链，再检查父级 LayoutGroup 的 Padding/Spacing、文本框及子节点实际宽高和 TMP Margin。修复落在已确认的 Prefab 文本与布局字段中；不靠补空格、随意位置偏移或运行时改字号/颜色/对齐来掩盖偏差，不新增适配辅助脚本。
- **动态文本按实际预期决定超长策略。** 依据业务已知的名称长度、数值范围、位数、单位或换行需求判断是否存在爆框风险，没有预期风险就不额外配置。存在风险时，单行内容检查横向空间，多行内容检查换行后的高度及对邻项的挤压。优先调整合理边距和可用空间，在设计允许时换行或让容器按既有布局规则伸展；沿用同一轴只有一个尺寸控制者的约束。确需缩小字号、Best Fit/Auto Size 或截断/省略时，按已确认设计配置，保留可读字号下限；关键数值、操作文案不得靠截断或蒙版隐藏问题，也不一律开启无限 Overflow。
- **检查最终渲染。** 在实际字体与布局重排完成后，观察文字的可见边界、上下留白、基线、遮罩/RectMask2D 裁切和与邻项的重叠；Text 的水平/垂直 Overflow 与 TMP 的换行、溢出、Auto Size 等配置按各自组件核实。Preferred Size 或属性值仅作辅助，不用“没有越出 RectTransform”替代文字完整显示的证据。
- **按用途选择验证样本。** 在基准尺寸及本次选定宽高比，固定文本使用实际文案；动态文本仅覆盖业务预期的内容范围，如最长名称、最大位数或确有需求的多行内容，多语言仅在需求包含时覆盖目标语言。动态内容替换后重新布局再检查对齐和已识别的溢出风险；预期范围不明时先查已有需求和代码依据，记录尚未确定项，不自行设定无限长度或为假设场景过度适配。临时预览用的测试文案验证后恢复，不写成正式默认内容。

把涉及的节点、固定/动态用途、实际预期、变化参数、采用原因和验证样本写进原 `02-Prefab减法与布局说明.md`；字号、字体、颜色和对齐动作与本轮其他 Prefab 动作合并到正式导出后的 Prefab 减法与适配清单，固定文本的动态防爆框项标为不适用。修改正式资产沿用已确认的 Prefab 清单范围，具体新冲突或范围扩张另行说明；用户已自行修正的适配按维护入口只检查和记录，不自动改回。

## 文字描边与阴影

适用于固定文本和动态文本。“阴影”“描边”“投影”统一归入文字 Effect 效果处理，名称差异不触发另一套材质、组件或运行时处理流程；固定文本不额外防爆框的约定不影响效果还原。PSD 中各子效果的开关和最终外观仍须分别核对，不能因归为同一类就把开启状态或视觉参数混为一个值。

- **先做逐效果证据表，后写 Prefab。** 每个文字效果分别记录当前固定 `_UI` 中的效果源路径、普通图层及祖先的可见性、图层样式总开关“效果”、该子效果自身小眼睛、当前阶段及关联字段所需 MD 的有效决定、刚生成 Prefab 当前值和目标值。普通图层或祖先关闭时，先核对是否属于已确认保留的运行时状态；只有非保留状态才不作为效果来源；效果总开关关闭时，整组 `fx` 均不采用；仅在总开关开启时，子效果自身关闭才表示只不采用该子效果，其他开启子效果仍可采用。已确认保留的状态根默认隐藏不构成上述否定证据，无论它是 Item 状态还是界面状态。历史效果表、待验证参数、旧 Prefab、旧预览和“同类文字”均不能覆盖这些状态；当前 PSD 与 MD 决定冲突、效果源缺失或无法判定时，停止该字段写入，列为待确认差异并更新对应 MD 后再执行。不得以“全量恢复”“批量统一”或导入器未解析样式为由跳过这张表。
- 仅当逐效果证据表确认当前设计采用时，才对照当前核验的 PSD 图层样式、设计参考与用户已保存的 Prefab 设置补齐描边或阴影。已有用户修正按维护入口保留，冲突不直接覆盖。效果已烘焙进切图或现有组件/材质已实现时，不重复叠加。
- UGUI Text 保留已有的 Unity 内置 `Outline` / `Shadow`，只在 Editor 的 Prefab 上调整其 effect 属性（如 `effectColor`、`effectDistance`），不新建效果组件或脚本。逐项按当前 PSD 与 MD 的有效决定处理，同时需要两种效果时按最终视觉核对组合结果。缺少所需组件时记录无法还原的差异，不以新增组件代替。
- **目标项目已有并确认采用 `Modify Effect` 时，TMP 文字效果复用该扩展。** 不论 PSD 将效果称为阴影、描边还是投影，Prefab 编辑阶段都只评估并修改已有 TMP 的 `m_modifyEffect` 字段，不改用材质 Outline/Underlay、UGUI Outline/Shadow 或其他效果组件，不新增脚本或修改 TMP 包。现有枚举仅提供描边类预设；视觉上可由它表达的效果按实际预览核验，柔和投影或独立多重效果不能表达时记录差异，不把名称统一误当成能力等价。`m_modifyValueEffectDistance` 只读，不得修改、清零或用默认值覆盖。完全关闭时只将 `m_modifyEffect` 设为 `NONE`，并读回核对距离字段未被改动。
- **目标项目未采用 `Modify Effect` 时，**按项目既有 TMP 方案和可用能力还原设计；不能还原时记录具体差异。所有路径都不得新建、复制或隐式实例化材质，不得创建 Material Preset、效果组件或脚本；这不要求删除已有 UGUI `Outline` / `Shadow`，其调整仍只限现有 effect 属性。不得改共享材质颜色影响其他使用者。已有用户设置仍按维护入口和 MD 处理，不擅自清除或迁移；检查效果扩张后的裁切与顶点开销。
- 按目标设计坐标、字体和预览结果核对效果，不把 PSD 的像素粗细直接视为 Unity 参数等值。检查效果扩展后的裁切、遮罩、边缘、偏移方向及可读性；固定文本使用实际文案即可。内置或现有能力不能还原的模糊、多重描边等效果，报告具体差异，不新增运行时辅助脚本或改写导入器。
- 在原第二份说明保留逐效果证据表，以及节点、效果依据、已有 UGUI `Outline` / `Shadow` 的 effect 属性或 TMP `Modify Effect` 枚举、只读核验的 `Modify Value Effect Distance`、颜色、关键参数与验证结果；每个最终保留文字节点的每项采用效果须以最终 Prefab 字段和对应资产版本的渲染结果核销。现有能力只能近似表达时，把具体视觉差异标为未精确还原，不能因预设已启用或文字无遮挡就判定效果通过。只有表中当前决定为采用且已实际写入的条目才纳入重生成后的适配恢复基线。发现此前违反该表写入的效果时，将该次写入标为无效恢复结果，暂停其作为后续基线；不自动回滚，按当前 PSD 与 MD 的逐字段清单经确认后通过项目规定的 Editor 通道修正。

对采用 `Modify Effect` 的 TMP，`Modify Effect` 与 `Modify Value Effect Distance` 必须一起读取和记录，但只有 `Modify Effect` 允许写入。`Modify Value Effect Distance` 是只读核验值，禁止修改、清零或用默认值覆盖；TMP 描边距离只能由 `Modify Effect` 的现有枚举控制。关闭或变更 TMP 效果时，只修改 `Modify Effect`，并读回记录 `Modify Value Effect Distance` 未被改动。UGUI Text 的 `Outline` / `Shadow` 只调整已有组件的 effect 属性，不适用此 TMP 字段限制。

本规则覆盖本节及历史记录中“自定义四向偏移”“使用 `m_modifyValueEffectDistance` 调整距离”的旧表述：这些字段只可读回核验，不得作为任何修改目标。

## 重导入与实际验证

涉及重新导出 PSD 时，先执行 [导出前整理稿检查](psd-preparation.md#导出前整理稿检查)，使用核验后的当前修正版，不能为重导入测试从源重生成来覆盖它。仅对已有 Prefab 重放后处理时不额外生成 PSD。

确认导入器覆盖范围后，在当前说明中记录可恢复的精简、已在 `_UI` 确定的模板方案、锚点和组件配置。只使用 Coplay MCP 的直接工具或请求载荷执行后处理；不为本流程新增外部配置文件或脚本。后处理只调整现成工具已生成的 Prefab，不承担切图、从 PSD 组装初始 Prefab、代码模板写出或绑定赋值；需要重新生成或刷新时调用现成工具的同一入口。记录 Coplay 工具名、参数摘要、结果和输出说明；连接异常按 [主规则的连接故障处理](../SKILL.md#coplay-连接故障处理) 自行恢复并核验，不追加接入提醒或确认；已核实原定工具本身不支持所需操作时记录具体限制，不换方法或以脚本重放替代。

重新生成前比较当前正式 Prefab 与当前阶段及关联字段所需 MD，对尚未记录或不一致的用户修改先列差异并取得确认，更新对应 MD 后再保留取值证据和可恢复资产。重新生成后，按已读取 MD 的当前有效记录决定精简、模板、锚点、布局及引用配置，旧正式资产只提供实际取值和核验证据。用户最新保存的适配只有经过差异确认并写入 MD 后才成为基线；不默认采用临时候选加合并的另一套主流程。核对生成器实际覆盖行为，保留正式资源 GUID 和有效引用；现成工具不能安全完成目标输出时，报告具体阻断，不改框架或导入器来绕过。

操作用稳定图层 ID、语义映射或经过校验的路径定位，并检查预期节点类型；匹配不唯一时停止该项，不能按模糊名称删节点。重复执行不得重复添加容器、组件或实例。

已有界面按 [复用记录与减少返工](existing-ui-maintenance.md#复用记录与减少返工) 先统一核验受影响节点及精确组件类型，再集中处理；对已知会被生成刷新重置的参数，在最后一次必要刷新后统一恢复并保存读回。预览复用已验证且包含显式清理入口的方法，不能仅凭成功返回验收空白图片；必要检查通过后不无故重复导出、截图或扩大回归范围。

至少检查以下实际结果，并按任务范围报告未运行的部分：

- 在基准与选定长宽比中预览，核对关键视觉、边距、遮挡及文字可读性；按 [字号、字体与颜色视觉还原](#字号字体与颜色视觉还原) 逐节点核对实际字体、字号配置、颜色与透明度链、缩放链和最终字形大小，再按 [文本对齐与溢出](#文本对齐与溢出) 检查固定文案的水平/垂直对齐及显示，仅对动态文本按实际预期验证内容变化及溢出风险，记录证据及未覆盖范围。
- 增减或隐藏显示项，确认布局重排、间距、顺序和尺寸；运行列表覆盖空列表、单项及设计允许的多项，检查隐藏模板不占位。
- 代码生成、必要手写引用修复、编译和刷新后重新加载 Prefab，检查 Mono 类型与序列化引用；涉及运行接入时验证显示、隐藏、重开和 Item 清理。
- `_@` 模板存在条件按钮时，逐一切换每个可见分支，确认对应 `_b` 的 Listener 和射线命中面位于按钮本体、回调只触发一次；隐藏分支不要求保留委托，复用或重开后再次验证可见分支重新注册。
- 本轮实际重新生成并按 MD 恢复后，比较最终结构、绑定、布局及 GUID/引用与记录基线；这次真实迭代可作为重放验证，不为验收强制额外导出一轮。确需额外重导入测试时先核对覆盖范围和授权，保护共享资源。仅有历史脚本而没有本轮 Coplay 实际调用时，明确注明其不可作为重放或验证证据。
